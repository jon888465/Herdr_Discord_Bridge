# ADR-0002：營運卡片存放於 plugin 狀態目錄並記錄流程

日期：2026-11-02。狀態：**已採納（Accepted，2026-11-02 使用者同意四項決定；同日補充決定 10）**。**部分取代 [ADR-0001](0001-portable-md-cards.md)**，範圍見文末「與 ADR-0001 的關係」。

> **本文只是決策，沒有任何程式或行為改變。** 營運卡片的位置、流程紀錄、`projects` 欄位與 bridge 的寫入都**尚未實作**；`CardStore` 目前沒有呼叫端，bridge 不讀寫任何卡片。

## 背景

ADR-0001 假設卡片是專案 repo 裡的 md 檔、用 git 保存歷史、執行態不進卡片。2026-11-02 與使用者討論後釐清：

- `docs/cards/` 與 `docs/card-examples/` 放的是**範例與設計文件**，不是營運資料。
- 實際開發用的卡片是 **herdr-discord-bridge 這個 plugin 自己的帳本**：記錄一張單從開單到結束的流程，像 log DB，**不進 git**。
- 各專案原本的 issue、README、CHANGELOG 等 md 照舊由 Agent 在專案裡寫，不由 bridge 代寫。
- 卡片要記錄這張單**改了哪個（些）專案**。

把卡片放在公開 repo 的 `main`（本專案 `origin` 為 PUBLIC）會遇到：`main` 有 ruleset，每次狀態變動都要開 PR；bridge 在被版本指紋監看的工作樹內寫檔，會改變指紋（`team ask --coding` 的指紋含未忽略的 untracked 內容）；Mantis 單可能含內部或客戶資訊，commit 進公開 repo 即公開；卡片進度與程式碼混在同一條 git 歷史，可能與分支衝突；多機器要自己同步 git。

## 決策

### 1. 營運卡片放在 plugin 狀態目錄，不進 git

- 位置：`<stateDirectory>/cards/`。`stateDirectory` 即 `src/config.ts` 的 `stateDirectory()`：環境變數 `HERDR_PLUGIN_STATE_DIR`，預設 `~/.config/herdr-discord-bridge/state`（目錄 0700，Team 任務的 journal 也在這裡）。
- 沿用 ADR-0001 的格式與工具：一卡一個 `.md`、受限 frontmatter 子集、`parseCard`／`serializeCard`／`importCard`、`CardStore(rootDir)`（`rootDir` 指向上述目錄）、`herdr-card-check`。
- `docs/cards/` 與 `docs/card-examples/` 維持範例與設計文件的角色，bridge 不讀寫它們。

### 2. 卡片是流程帳本（取代 ADR-0001 決定 2「執行態不進卡片」）

卡片記錄從開單到結束的流程：進度、結果、異動專案。卡片分兩個區域，寫入者不同：

| 區域 | 寫入者 |
|---|---|
| frontmatter 的需求欄位、`## 描述`、`## 驗收條件`、`## 待確認` 等 | 人（含 Agent 協助轉換） |
| `status`、`updated`、`projects`、`## 異動專案`、`## 流程紀錄` | bridge |

bridge 只**追加**到自己的區域，不改人寫的內容。

### 3. Journal 是執行狀態的權威來源，卡片紀錄由事件衍生且可重複寫入

Team 任務的 journal（`src/team-task-store.ts`）已是執行狀態的權威來源。卡片的流程紀錄由 journal 事件衍生，每筆帶事件 id，重複寫入同一事件不產生重複的紀錄行。卡片遺失或損壞不影響 journal 與任務執行。

### 4. 異動專案

- frontmatter 以 `projects: [專案名, ...]`（純量陣列，現有格式即可表達）取代單一的 `project` 欄位，方便搜尋與列表。
- 詳細資料由 bridge 追加在內文 `## 異動專案`，每個專案一段：機器、repo 路徑、分支、worktree 路徑、base 與 head commit、PR 連結（完整網址）。
- 現有 `project` 欄位暫時仍被接受以相容既有範例，之後移除。

### 5. 流程紀錄（提議的形式，細節於實作時定）

`## 流程紀錄` 只追加，每行一個事件：

```text
- 2026-11-02T08:15:00Z | started | 在 agy-pod 建立 worktree，分支 card/REQ-20261102-example | ev:3f2a9c
```

欄位為時間、事件名、單行說明、事件 id。說明不得含換行。

### 6. 專案文件不由 bridge 代寫

issue、README、CHANGELOG 等由 Agent 在該卡片的 worktree 裡依專案自己的規則修改，隨 PR 一起進專案。bridge 只彙整**結果**到卡片，不替專案寫文件。

### 7. 刪除與保留

卡片是狀態目錄裡的檔案，使用者可以手動刪除。已結束的卡被刪不影響系統；對應任務**執行中**時卡片被刪：暫停並詢問使用者（沿用 ADR-0001 決定 7），journal 仍在。

### 8. 多機器

卡片只存在跑 bridge 的那台機器；遠端 Herdr 機器不放卡片、不需要同步。`## 異動專案` 記錄每個專案所在的機器。

### 9. 隱私

狀態目錄 0700，卡片不進 git，因此 Mantis 等內容不會進入公開 repo。內容只在使用者主動匯出（Mantis、Notion）時離開。bridge 不應把 Agent 輸出中的機敏內容寫進卡片（見未決 4）。

### 10. 流程紀錄的大小：先提高上限，超過再輪替到旁檔

使用者決定（2026-11-02）：不為了 256 KiB 的整檔上限而限制紀錄，**先提高上限，真的超過再把舊紀錄放到旁檔**。

- **兩種上限分開：** 匯入來源不可信，維持 256 KiB；bridge 自己管理的營運卡片使用較高的上限。提議值（**待使用者確認**）：營運卡片整檔硬上限 **1 MiB**，輪替門檻 **768 KiB**（硬上限的 75%，保留空間給單次追加）。`parseCard` 需要改成可帶上限參數。
- **輪替：** 追加一筆紀錄後若整檔會超過輪替門檻，bridge 把較舊的紀錄移到旁檔，**卡片只保留最近 5 筆紀錄**（使用者決定，2026-11-02），其餘全部移走，並留下一行指向旁檔的說明。旁檔沿用同樣的紀錄行格式，只增不改。輪替後卡片的大小大致回到沒有紀錄時的大小，因此輪替不會頻繁發生。
- **旁檔命名與位置：** `<stateDirectory>/cards/logs/<卡片 id>/0001.md`、`0002.md`…。**不可與卡片同層、也不可叫 `REQ-….md`**：目前 `CardStore` 的 `CARD_FILE`（`/^(REQ|TKT)-.*\.md$/`）會把任何這類檔名當成卡片，旁檔會被列為損壞的卡片。放在 `logs/` 子目錄下，`list()` 與 `existingIds()` 就不會看到它們。
- **崩潰安全：** 先建立旁檔（以不覆蓋的方式），再用雜湊比對更新卡片。兩步之間崩潰會讓同一批紀錄同時存在於旁檔與卡片；因為每筆紀錄有事件 id（決定 3），讀取時以事件 id 去重，重複不造成錯誤。
- **單筆紀錄要有長度上限：** 「保留 5 筆」只有在每筆都是有界的單行時才保證卡片縮小。長度上限於實作時定（見未決 8）。若人寫的內容本身就超過輪替門檻，輪替無法使卡片縮小，視為無法輪替，走下一項的保護。
- **超過硬上限的保護：** 輪替要保證卡片永遠不超過硬上限；若無法輪替（例如旁檔寫入失敗），bridge 拒絕追加並回報錯誤，而不是寫出無法解析的卡片。
- **實作影響：** 256 KiB 目前寫死在三處：`src/card.ts`（`parseCard`）、`src/card-store.ts`（`CardStore` 讀檔上限）、`src/card-check-cli.ts`（驗證指令）。都需改為依用途帶入上限。

## 後果

- 好處：不需要為狀態變動開 PR；不弄髒工作樹、不影響版本指紋；內容不進公開 repo；沒有 git 歷史衝突；多機器不需同步；格式與已寫好的程式幾乎都能沿用。
- 代價：卡片沒有 git 歷史，流程紀錄必須自己累積；卡片的備份依賴狀態目錄本身；卡片與 journal 是兩份記錄，需靠「journal 為權威、卡片衍生且冪等」避免不一致；流程紀錄會成長，因此需要提高上限並在超過時輪替到旁檔（決定 10），輪替增加了實作複雜度。

## 替代方案

- **專案 repo 內 `.gitignore` 的資料夾**：每個專案各一份；一張卡改多個專案時沒有自然的位置；多機器各一份。
- **獨立的私有 cards repo**：每次狀態變動要 commit（若有 ruleset 還要 PR）與同步，成本高。
- **SQLite 等資料庫**：不符合 ADR-0001 對可攜、可匯出匯入 md 的要求。使用者以 log DB 作比喻，指的是「帳本」的角色，不是儲存技術。

## 驗收條件（實作時）

- 卡片建立於 `<stateDirectory>/cards/`；目錄 0700、檔案 0600；不寫入此目錄以外的位置。
- 開單到結束的各階段都在 `## 流程紀錄` 留下紀錄；同一事件重複寫入不產生重複行。
- 人在編輯人寫區的同時 bridge 追加紀錄：雜湊衝突被偵測，不丟失人的修改（沿用 `CardStore.update`）。
- `projects` 欄位與 `## 異動專案` 對應實際被改的專案與機器；`project`（舊欄位）仍可讀。
- 卡片不在任何專案 repo 內，專案的 `git status` 不因卡片而變髒。
- 執行中的卡片被刪除時暫停並詢問，不默默繼續或取消。
- 流程紀錄達到輪替門檻時，舊紀錄移到 `logs/<id>/` 旁檔，卡片保持可解析且不超過硬上限；旁檔不被 `list()` 當成卡片。
- 輪替後卡片恰好保留最近 5 筆紀錄（不足 5 筆時全部保留），較舊的全部在旁檔，旁檔依序編號、內容不重不漏。
- 輪替兩步之間模擬崩潰：同一批紀錄同時存在於旁檔與卡片，讀取以事件 id 去重後沒有重複。
- 旁檔寫入失敗時拒絕追加並回報，卡片不被寫壞。
- 匯入仍使用 256 KiB 上限，營運卡片使用較高上限，兩者不互相放寬。
- 寫入的紀錄不含機敏內容（規則見未決 4）。

## 未決

1. ~~流程紀錄與 256 KiB 上限~~ 使用者已決定「先提高上限，超過再放旁檔」，見決定 10。輪替後卡片保留最近 5 筆（使用者決定）。仍待確認的是具體數字（提議：硬上限 1 MiB、輪替門檻 768 KiB）。
2. `projects` 的專案名稱規則：用 Herdr workspace 對應的 repo 目錄名？同名時如何區分（加機器前綴）？

4. **機敏內容。** bridge 把 Agent 輸出彙整進卡片，可能寫入密碼、token 或客戶資料。需要與現有「Report 是有界的觀察輸出，不分享隱藏推理」的規則一致，並定義截斷與過濾。
5. `CardStore` 需要新的 API（例如受限的追加紀錄、只改 bridge 區域），並把檔案權限由 0644 改為 0600。
6. 啟動時建立與檢查狀態目錄權限；狀態目錄被其他使用者可讀時的處理。
7. 卡片的索引、搜尋與列表（例如依 `projects` 或 `status`）。
8. 單筆流程紀錄的長度上限與截斷規則（與未決 4 的機敏內容過濾一併處理）。

## 與 ADR-0001 的關係

| ADR-0001 決定 | 本 ADR |
|---|---|
| 1. 一張卡一個 md、檔案是真相來源、版本歷史交給 git | 一卡一個 md 不變；**「版本歷史交給 git」被取代**：卡片不進 git，歷史由 `## 流程紀錄` 累積；預設位置由專案內 `docs/cards/` 改為狀態目錄 |
| 2. 執行態不進卡片 | **取代**：卡片記錄流程 |
| 3. Frontmatter 受限子集 | 不變 |
| 4. 欄位 | 新增 `projects`；`project` 被取代（暫時相容） |
| 5. 狀態與寫入權 | **擴充**：bridge 另可追加 `projects`、`## 異動專案`、`## 流程紀錄` |
| 6. 寫入安全 | 不變，另加檔案權限 0600 |
| 7. 刪除語意 | 補充：位置改為狀態目錄；執行中被刪的處理不變 |
| 8. 匯入匯出 | 不變 |
